# Pocketforge product and UI review

Review date: 2026-11-03

## Scope and method

This is a clean-room product and UI review of the publicly accessible Pocketforge app, its published user guide, and its publicly served browser bundles. I inspected the empty campaign picker and new-campaign dialog at 390 × 844, and used a 1440 × 900 desktop viewport for an in-campaign walkthrough. For that walkthrough I created a clearly named temporary campaign (`Ironvibes temporary inventory audit`), map (`Ironvibes audit map`), and audit records, then exercised available screens and actions. These were test data, not user campaign data. After following an external license link the recovered tabs briefly rendered an empty picker, but the same audit campaign and map later reappeared and the walkthrough resumed. No import file was selected, no campaign import was performed, and no cleanup or rollback was attempted. Notes below distinguish direct observation, published-client evidence, guide-derived behavior, and unverified areas. The inspected JavaScript source map returned 404; minified browser code was available. No Pocketforge code or artwork was copied into Ironvibes.

## Published organization and workflows (guide-derived unless noted above)

- **Campaign setup:** choose a setting/content theme separately from character rules; settings drive default origins, oracle and move context, available site categories, character tracks, and conditions.
- **In-campaign workspace:** app header and settings, main navigation tabs, a contextual sidebar for moves/oracles, quick-roll affordances, and a dice roller available from the lower UI. The panel inventory and one Face Danger miss were directly observed; dice mechanics were not fully exercised.
- **Hero and NPC records:** create/edit, randomly fill fields, assign origins, assets, stats/conditions and relationships; promote NPCs to heroes or vice versa; export/reuse records.
- **Tracks and vows:** track journeys, vows, exploration, combat, and scene challenges.
- **Sites/instances:** Delves, Derelicts, Vaults, Shipwrecks, Caves, and Ruins with progress, areas/zones, waypoints, and generated features; users can edit or reroll output. The audit inspected the Sites creation dialog only; these richer workflows are guide-derived.
- **Locations and factions:** link characters, NPCs, quests/missions/troubles, and nested locations.
- **Custom data:** user-created assets, themes/domains, and custom oracle tables (the latter is present in recent public announcements; confirm UX/format during implementation).
- **Journaling:** insert oracle results, continue writing while navigating elsewhere, and export campaign journals as styled HTML.

## UX patterns worth carrying forward

1. Separate campaign content selection from mechanical character rules.
2. Keep contextual oracles/moves close to the journal and active view, rather than requiring navigation to a separate reference screen.
3. Make generated values editable and rerollable; generation should support play, not take control away from the player.
4. Keep campaign and content import/export visible in the settings model.
5. Adapt navigation and sidebar behavior on mobile while keeping the desktop workspace spacious without a permanent rail or tool panel.

## Clean-room implementation boundary

Ironvibes is independently implemented. We can borrow general workflow ideas and product organization, but should not copy Pocketforge source, branding, visual assets, or distinctive screen designs. Datasworn's JSON schema and content packages are a separate, documented interoperability format for rules data.
